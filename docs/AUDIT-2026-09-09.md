# Front-end audit, 2026-09-09 (branch design-v4-1, main 65aac5d)

Full route × viewport pass on the v4.1 build, then a fix pass and a re-run. Founder brief: docs/FRONTEND-V4.1.md follow-up ("FULL FRONT-END AUDIT + FIX PASS"). Tracking: issue #19.

## Method

- Target: the local production build (`next build` + `next start -p 3077`) of design-v4-1 at 65aac5d; Lighthouse against the Vercel preview of the same commit.
- Driver: chrome-devtools MCP for every emulation, probe and screenshot (tabs rotated every ~150 calls: a tab stops answering `captureScreenshot` after that many emulations). Playwright only for the reduced-motion auto-advance check the MCP browser cannot run (its Chrome reports `prefers-reduced-motion: reduce`).
- Routes (10): `/`, `/pricing`, `/faq`, `/privacy`, `/terms`, `/support`, `/the-math`, `/w/example`, `/w/example-2`, 404 (`/does-not-exist`). Plus five states on `/`: the pre-order modal open, and the switcher on screens 2, 3 and 4 (screen 1 is the default in the full-page shot).
- Viewports (17): phones 320×568, 375×667, 390×844, 430×932 (iOS Safari UA; full pages at DPR 1 for layout, viewport shots at DPR 3 for sharpness), 844×390 landscape; tablets 768×1024, 834×1194, 1024×1366 portrait and 1024×768, 1194×834, 1366×1024 landscape (iPad UA); desktops 1280×720, 1440×900, 1920×1080 (full pages at DPR 1, fold + modal at DPR 2).
- Full-page capture: puppeteer's `fullPage` times out under mobile emulation, so every full page is a viewport capture with the viewport set to the document height (`content-visibility: auto` sections are inside the viewport and render). 1024×768 landscape shares its layout width with 1024×1366, so it has fold shots per route plus the modal and switcher states; its full pages are the portrait files.
- Per cell: `scripts/audit-probe.js` (copied to `public/_audit/probe.js` for the run; that copy is gitignored) evaluated in the page (horizontal overflow and offenders, single-line truncation, heading orphans, cut-out/arrow overlaps, tap targets under 44px, inputs under 16px, header height and shadow at 0 and 600px, loaded fonts and any retired family, computed colors outside the token palette, WCAG contrast on every text element against its composited background, inline `vh`), then the screenshot. Modal cells add dialog, badge, card and close-button rects; switcher cells add panel and arrow rects and the active tab.
- Eye review: every capture cut into 1000px columns and tiled (`scripts/audit-sheet.ts`), every sheet read; 200% crops of the DPR-3 hero and share-card thumbnails (`design/shots/audit-2026-09-09/before/crops/`).
- Behavior: anchors `/#how` and `/#pricing` (land under the sticky header), back after the `/thanks` 301, scroll restoration on back, modal Tab wrap / Shift+Tab / Esc / focus return / backdrop at 320 and 390 (and 1440 earlier today), arrows + ArrowLeft/Right + dots, focus rings on every visible focusable, `:hover` rules in the built CSS vs `@media (hover: hover)`, `vh` in source, safe-area padding.
- Performance: `npx lighthouse` 13.4 mobile (`--form-factor=mobile --screenEmulation.mobile`) and desktop (`--preset=desktop`) per route on the preview.
- Files: `design/shots/audit-2026-09-09/before/<route>[-state]__<w>x<h>@<dpr>[-landscape][__fold].png`, `.../before/sheets/`, `.../after/` for the re-run (223 captures + 68 sheets each). The full sets (123 MB) stay on disk and are gitignored; the 19 before/after pairs the findings cite are committed under `.../evidence/before/` and `.../evidence/after/` with the same file names.
